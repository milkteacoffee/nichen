# 1. 先定位：我们"像 PPT"的三个根因

> 结论先行：**不是缺美术，是缺"每帧都在变的东西"**。逐帧看下来，屏幕上 90% 的像素在两次
> 刷新之间完全一样 —— 这在感知上就等于静止。

| # | 根因 | 证据（代码） | 观感 |
|---|---|---|---|
| P1 | **行走等于没动画** | `explore.js:189` `frame = 1 + floor(walkT/.18) % 2`，但 `.0/.1/.2` **三帧登记的是同一张图**（`assets-build.py` 的 HERO_DIRS 说明） | 角色"滑行"过去，脚不动 |
| P2 | **场景完全静止** | 地面预烘成一张静态层（`_ensureGround`）、装饰走 3 档预烘（`decorScaled`），**没有任何随时间变化的绘制** | 树不摇、水不动、云不飘 |
| P3 | **转场与反馈是硬切** | 遇敌只有闪白（`flash`）；切场景直接换图 | 像翻幻灯片 |

> 战斗侧**已有**：受击抖动（`battle.js:1713`）、暴击更强抖动、濒死红屏呼吸。
> 所以"PPT 感"主要集中在**探图**，不是全局问题 —— 这决定了改造成本不高。

# 2. 对标：主流游戏怎么让角色"活过来"

## 2.1 《宝可梦》（GB/GBA 时代，2D 像素）

| 手法 | 具体做法 | 我们能抄的 |
|---|---|---|
| **走路 4 帧循环** | 每方向 2 帧交替（左脚/右脚），**每走一格切一次** | 我们缺的是**真帧**。不一定要重画 —— 见 §3.1 的程序化方案 |
| **遇敌转场** | 屏幕**闪 3 次 + 快速放大**（螺旋/圆环擦除），约 0.6s | 我们现在只有一次闪白 |
| **水面动画** | 水格用**独立帧表**，每 0.4s 换一帧 | 地面是预烘的 → 需要**叠加一层动态** |
| **花草摆动** | 部分图块有 2 帧摇摆 | 同上 |
| **战斗入场** | 玩家立绘**从右滑入 + 敌人从左滑入**，各 0.3s | 我们是直接出现 |
| **血条掉血** | 血条**缓慢追平**（不是瞬间跳） | 我们是瞬间 |
| **升级特效** | 金光扩散 + 角色闪白 | 无 |

**核心洞察**：宝可梦的"活"**不靠帧数**，靠**状态切换时的过渡**（入场滑动、血条追平、转场擦除）。
它静止时也是静止的。

## 2.2 《烟雨江湖》

| 手法 | 具体做法 | 我们能抄的 |
|---|---|---|
| **角色脚下有影** | 角色/ NPC 脚下都有椭圆阴影，**移动时阴影跟着** | 我们有 `shadowEllipse`，但探图里的角色没有 |
| **待机呼吸** | 站立时角色**极缓慢上下浮动**（~2s 周期） | 无 |
| **地图粒子** | 场景里有**飘落的叶/雪/尘**（很稀疏，5~15 个） | 无 |
| **点击落点反馈** | 点地后目标格**闪一下光圈**再走 | 我们有 `mark` 但很弱 |
| **行走拖影** | 快速移动时留 1 帧残影 | 无 |
| **界面过渡** | 面板**从下往上滑入**，不是直接出现 | 我们是直接出现 |

**核心洞察**：烟雨江湖的"活"靠**低频、低成本的持续动效**（阴影 + 呼吸 + 粒子），
每一项单独看都微不足道，叠起来就是"这是个活的世界"。

## 2.3 共性总结（可执行的四条）

1. **每个可动的东西都要有相位**：树、草、灯、水面、NPC —— 相位按坐标派生，
   这样相邻的树**不同步**，看起来才自然（同步摆动比不动更假）。
2. **过渡比帧数重要**：入场/退场/切换都要有 0.2~0.4s 的补间。
3. **反馈要"过冲"**：受击不只是掉血，还要**抖 + 白闪 + 数字上浮**。
4. **静止时也要有一点点动**：呼吸、粒子、云影 —— 让屏幕**永远不是完全静止的**。

# 3. 我们的方案（按"性价比"排序）

> 原则：**能用程序化变换解决的不出图**；只有"真帧"这种非出图不可的才列入出图清单。

## 3.1 P1：行走动效 —— 程序化"走路感"（**零出图**）

不重画三帧，改用**叠加变换**做出步伐感（`explore.js` 绘主角处）：

| 变换 | 公式 | 观感 |
|---|---|---|
| **上下浮动** | 走路 `-abs(sin(π·步数)) * 2.2px`；待机 `-sin(t·1.3) * 0.6px` | 每步一沉一浮 |
| **左右倾摆** | `sin(π·步数) * 0.035 rad`（±2°） | 身体随步伐左右摇 |
| **挤压拉伸** | `y 缩放 1 + sin(2π·步数) * 0.035` | 落地压扁、抬脚拉长 |
| **脚步阴影** | 脚下椭圆阴影，**随浮动反向缩放** | 一眼看出"离地"了 |

> 这四条叠起来，静止图也能读出"在走"。**这是本轮性价比最高的一项。**

## 3.2 P2：环境动效 —— 三层（**零出图**）

| 层 | 做法 | 成本 |
|---|---|---|
| **摇摆层** | 树/草/竹：`sin(t·1.6 + 相位)` 水平偏移 ±1.2px，**相位由格子坐标派生** | 极低（一次 translate） |
| **灯火层** | 灯/火把：alpha 呼吸 `0.85 + 0.15·sin(t·4 + 相位)` | 极低 |
| **粒子层** | 按**区域主题**撒 12~24 个缓慢飘落的粒子（凡界落叶 / 灵界雨丝 / 仙界云絮 / 道界道纹光点 / 火云谷火星 / 广寒宫雪） | 低（一帧 20 个 2px 矩形） |

> ⚠️ 粒子**必须用 `G.game.time`**（不是 `performance.now()`）—— 否则截图与契约都没法钉。

## 3.3 P3：转场与反馈（**零出图**）

| 场景 | 现状 | 改为 |
|---|---|---|
| 遇敌 | 只闪白 | 闪白 ×2 + **镜头缩放脉冲**（1.0→1.06→1.0）+ 轻微抖动，总时长 ~0.5s |
| 切场景 | 直接换 | 已有闪白；补**淡入**（0.25s） |
| 面板打开 | 直接出现 | **从下往上滑入** 0.18s（`G.UI.panel` 的 y 偏移补间） |
| 点地寻路 | 落点标记很弱 | 落点**扩散光圈**（半径 4→14px，alpha 1→0，0.4s） |
| 伤害数字 | 无 | 受击时**数字上浮**（-16px，0.6s）+ 暴击金色更大 |
| 血条 | 瞬间跳 | **追平**（每秒掉 60% 差值） |

## 3.4 御剑飞行（金丹境+）

### 3.4.1 触发与表现

| 项 | 规则 |
|---|---|
| 解锁 | `globalLevel >= 金丹`（见 §3.4.2 的 gl） |
| 切换 | HUD 上常驻「御剑」按钮（未解锁时置灰并提示境界要求）；也可按 `F` |
| 速度 | 移速 **×1.8**（`MOVE_T` 0.18 → 0.10） |
| 通行 | **可越过 `tree`/`rock`/`furn` 等低矮阻挡**；**不可越**边界、建筑、`wall`/`wallrock` |
| 遇敌 | **飞行时不触发暗雷**（这是"飞"最直观的收益） |
| 绘制 | 角色**整体抬高 6px** + 脚下**剑光**（一条斜置的青白光刃 + 拖尾残影 2 帧） |
| 落地 | 切回步行时**下坠 6px + 一圈尘环** |

### 3.4.2 gl 门槛

按《境界体系 v3.2》的 19 境：**金丹** 的 gl 区间需与 `player.js: REALMS` 对齐，
代码里取 `Player.realmOf(gl).n === '金丹'` 的 `y0` 作为门槛（**不写死数字**，
境界表一改门槛自动跟着走 —— 写死就会在境界调整后失准）。

### 3.4.3 为什么这样做能"飞起来"

2D 俯视没法真的表现"高度"，能用的只有三个视觉线索：

1. **离地**：脚下阴影**变小 + 变淡**，角色**抬高** —— 这是最有效的"高度"暗示
2. **速度**：移速提升 + **拖影**（残影帧）
3. **光效**：脚下的剑光与拖尾

三条叠起来，玩家就会自己脑补出"在飞"。

# 4. 宗门：对标与补强

## 4.1 主流做法

| 游戏 | 宗门的核心机制 | 对我们的启发 |
|---|---|---|
| **《鬼谷八荒》** | 宗门有**等级/贡献/职位**，弟子每月领俸、接宗门任务、升职；宗门之间会**互相攻打** | 我们已有贡献与位阶 → 缺**任务**与**职位收益** |
| **《太吾绘卷》** | 门派有**独门功法树**，学功法要**拜师 + 满足前置**；叛门有代价 | 我们已有互斥 → 缺**前置链**（高阶功法要先学低阶） |
| **《烟雨江湖》** | 门派任务**每日刷新**，有**门派专属商店**，声望换物 | 缺**每日任务**与**门派商店** |
| **《凡人修仙传》** | 散修与宗门是**资源差**：宗门有秘境、灵田、丹房；散修靠机缘 | 我们的散修侧**太单薄** |

## 4.2 我们的补强（S3–S5 细化）

| 期 | 内容 | 对标来源 |
|---|---|---|
| **S3** | **宗门任务**：每日 3 件（采药/巡山/护送），完成给贡献；**贡献换门派商店**（丹药/符箓/材料） | 鬼谷八荒 + 烟雨江湖 |
| **S3** | **功法前置链**：本门第二本功法需要**第一本达 Lv3** 才能兑换 | 太吾绘卷 |
| **S4** | **职位收益**：外门/内门/真传各有**月俸**（每 30 天结算一次灵石 + 丹药） | 鬼谷八荒 |
| **S4** | **散修侧补强**：散修盟（灵界 L1）可**自由交易**、**接悬赏**（杀指定妖兽换灵石） | 凡人修仙传 |
| **S5** | **自创宗门** + 宗门徽记 + 总部场景 | 太吾绘卷 |
| **S5** | **门派争斗**（可选）：两宗声望对抗，胜方功法打折 | 鬼谷八荒 |

# 5. 副本：对标与补强

## 5.1 主流做法

| 游戏 | 副本的核心机制 | 对我们的启发 |
|---|---|---|
| **《烟雨江湖》** | 副本有**前置剧情**、**机关解谜**、**多结局**（选不同的路拿不同的东西） | 我们的副本是纯战斗推进 → 缺**非战斗交互** |
| **《鬼谷八荒》** | 秘境有**随机事件**（遇到商人/陷阱/机缘），每次进去不一样 | 缺**随机房间事件** |
| **《暖雪》** | 每关结束有**三选一强化**（Roguelite 核心） | 我们是固定掉落 → 缺**每层选择** |
| **《以撒的结合》** | 房间类型多样（宝箱房/商店/诅咒房） | 缺**房间类型** |
| **《暗黑破坏神》** | 精英怪有**词缀**（词缀组合让同一只怪不同打法） | 缺**词缀** |

## 5.2 我们的补强

| 优先级 | 内容 | 对标 | 说明 |
|---|---|---|---|
| **高** | **副本内随机事件房** | 鬼谷八荒 | 每层 20% 概率是事件房：商人（卖丹药）/ 机缘（免费强化）/ 陷阱（掉血）/ 古碑（给碎片） |
| **高** | **每层三选一强化** | 暖雪 | 通关一层后从 3 个临时增益里选 1（本场副本内有效，出副本清空）——**这是 Roguelite 的灵魂** |
| **中** | **精英词缀** | 暗黑 | 杂兵 15% 概率带词缀（狂暴/护盾/吸血/剧毒），名字前加前缀 |
| **中** | **副本前置剧情** | 烟雨江湖 | 每个副本首次进入有一段 2~3 句的场景描写（由天道生成或写死） |
| **低** | **多结局** | 烟雨江湖 | 大副本第 8 层给两条路：一条通 Boss（快）、一条绕路拿宝箱（慢） |

> **最该先做的是「每层三选一」** —— 它把"打怪升级"变成"构筑"，是 Roguelite 与
> 线性 RPG 的分水岭。我们已经是轮回制（Roguelite 骨架），但没有构筑环节，这是最大的缺口。

# 7. 验收口径（怎么证明"活了"）

| 项 | 判据 |
|---|---|
| 行走 | 连续走 3 格，角色**纵向位移有非零变化**（不能只有 x 变） |
| 环境 | 同一场景**间隔 0.5s 取两帧**，装饰层像素**必须不同** |
| 粒子 | 粒子数 > 0 且**位置随 time 变化** |
| 转场 | 遇敌时**镜头缩放**在 0.5s 内离开 1.0 再回到 1.0 |
| 御剑 | 飞行时**移速更快**、**不触发暗雷**、角色**离地抬升** |
| 三选一 | 每层结束**必出 3 个候选**，选 1 后**本场生效**、出副本**清空** |

> ⚠️ 这些判据都**不能只断言"不抛异常"** —— 必须是**数值/像素级的差分**。
> 本项目已经踩过太多次"静默不画"的坑。
