## 1. 总则：没有“等级”，只有境界与品级

- 游戏内**禁止出现面向玩家的“等级 / Lv / X 级”**；一切成长归到两条正交坐标：
  - **境界**：修行者（主角 / 灵兽 / 友好 NPC / 敌对 NPC / 妖兽）的修为层次，全角色**共用一套**。
  - **品级**：物品 / 道具 / 装备 / 丹药 / 材料的成色档位。
- 功法是特例，含两个坐标：**功法品阶 tier**（功法的品级）+ **功法修炼境界（九重×四阶段）**；同样不出现“等级”。
- 内部实现可保留名为 `level` / `lv` / `globalLevel` 的字段（其值**就是细 gl 或功法进度**），但**所有玩家可见文案**必须经 helper 转成境界/品级名。

## 2. 境界系统（全角色共用）

### 2.1 两套刻度：细 gl（1–684）与压缩阶 scaleLevel（1–171）

人物大境界与功法对齐：**每个大境界含九重，每重再分 初期 / 中期 / 后期 / 巅峰 四个小阶**，
故**每大境 9×4 = 36 阶，全 19 境共 684 阶**，这是唯一的细进度坐标 `gl`。

- **细坐标 `gl`（1–684，`save.globalLevel` / `MAX_GL=684`）**：
  大境 r（0 基）覆盖 `r*36+1 … r*36+36`；
  `realmPos(gl)→{r, stage(1–36), chong(1–9), phase(0–3)}`。
- **压缩阶 `scaleLevel(gl) = r*9 + chong`（1–171）**：把同一重的初/中/后/巅压回同一刻度。
  - **数值成长（气血/攻击/防御/速度）与技能解锁一律走压缩阶 Ls**——同重内四小阶数值相近，四阶主要作**称谓**。
  - 这样既给玩家“九重×四阶”的细腻层次，又让敌人/Boss/灵兽的数值曲线与旧 1–171 刻度**等价、零漂移**。
- **称谓 `stageName`**：输出 `{大境}{中文数字}重{初/中/后/巅}`，如 `淬体二重初期`、`大罗金仙九重巅峰`；
  `realmInfo(gl).n` 即全名。`CN=['一'..'九']`、`CH_PHASE=['初期','中期','后期','巅峰']`。
  量词统一用「重」（不再有淬体称“段”、准圣称“转”的旧特例）。

### 2.3 灵气需求 needQi 与破境

- `needQi(save, gl) = round( 100 × gate × 22.8 × u² × calib × (1+breakCut) )`，其中
  `u = stage/36`、`gate` 每大境翻倍（淬体 1 … 道祖 262144）、`calib` 淬体 0.4 其余 1，`Math.max(1)`。
- 每大境灵气总量（gate×100×285 递推）：淬体 ≈ **11,400**、炼气 ≈ **57,000**、筑基 ≈ **114,000**，逐境翻倍。
- **破境 `breakState`**：
  - `big = stage>=36`（该大境九重巅峰）；`ready` 需 `have>=need` 且**大境突破须持破境丹**，随后渡**心魔劫**。
  - 小阶（初→中→后→巅、以及跨重）只积灵气即可，不需丹药、不渡劫。
  - `worldcap`（gl 已到本界封顶）拦截：提示先通关当前界大副本飞升，而非继续破境。
- ⚠️ **勘误（v3.6）**：`player.js REALMS` 筑基条目曾误写 `caib`（应为 `calib`），导致筑基 36 阶 needQi 全 NaN；已校正并由探针回归。

### 2.6 适用对象（口径一致）

| 对象 | 境界来源 | 数值缩放 |
|---|---|---|
| 主角 | `save.globalLevel`（峰值 `save.maxGlobalLevel`），细 gl 1–684 | 压缩阶 scaleLevel |
| 灵兽 | 个体细 `gl`，**≤ 主角当前 gl**，随喂养/出战提升（《灵兽 v1.1》） | 压缩阶 scaleLevel |
| 友好 NPC | 数据补细 `gl`（沈伯、刘掌柜；宗门 NPC 见宗门小世界 §4） | 压缩阶 |
| 敌对 NPC / 妖兽 / Boss | `makeEnemy(species, L)`，**L 即细 gl**；属性按 scaleLevel(L) 缩放、技能按 gl 解锁 | 压缩阶 |

- 敌人/Boss 名号在不同界只换前缀与名（如 `【凡界*魔道宗宗主】`），**机制相同、数值随界系数与难度抬升**。

## 3. 功法修炼境界：九重 × 四阶段（`grades.js`）

- 每门功法**最高九重**，每重分 **初期 → 中期 → 后期 → 巅峰**；共 **prog 1–36**，**九重巅峰为最高**。
- helper：
  - `G.Data.skillRealm(prog)→{chong,phase,n,short}`，n 如「三重·中期」、short 如「三重中期」。
  - `G.Data.skillAtTop(prog)`（prog≥36）、`G.Data.SKILL_MAX_PROG=36`。
- 属性贡献沿用线性（攻 prog×5 / 防 prog×3 / 血 prog×20，乘品阶系数与灵根系数），36 封顶：单门至高 +180 攻。
- **封顶拦截**：「精进」「修炼」到顶置灰显「已至九重巅峰」；「参悟」已到顶功法不进候选。
- 显示：功法详情、下拉列表/头、储物「功法」格、宗门页本门功法，全部用 `skillRealm` 名，无 Lv。

### 3.1 功法获取（统一四途径，详见宗门小世界 §6）

任务奖励 / 刷野怪（碎片+Boss 整本）/ 打副本（碎片+整池）/ **小世界探索（传承之地、宝箱、宗门秘境）**。
宗门功法（src='sect'）只走宗门途径、不进野外碎片池；散修功法走 free；通用三本两道皆可。

## 4. 物品品级（11 档 + 道级预留）

### 4.1 品级阶梯（`grades.js G.Data.grades`）

| 序 | 品级 | 序 | 品级 |
|---|---|---|---|
| 1 | 下品 | 7 | 地级 |
| 2 | 中品 | 8 | 天级 |
| 3 | 上品 | 9 | 神级 |
| 4 | 极品 | 10 | 仙级 |
| 5 | 黄级 | 11 | 圣级 |
| 6 | 玄级 | — | **道级（道界专属，超出常规 11 档，单独标记）** |

- helper：`grades.list / idxOf(name) / nameOf(i) / isValid(name)`；`grades.dao='道级'`。

### 4.2 落位

- **装备/法宝**：补 `grade` 字段并在「法宝」相关面板显示；示例：青锋剑下品、赤霄刀上品、点钢枪极品、方天戟玄级、寒星项链地级、摄魂铃/照妖古镜黄级。
- **丹药（破境丹）**：`PILL_QUALITY` 对齐顺序（…天级 → 神级 → 仙级 → 圣级；道级预留），`pillQualityIdx(gl)` 单调不降。
- **材料 / 道具 / 妖兵 / 鞍具**：统一走该品级阶梯；资源存 `save.items`，不另立背包。

### 4.3 功法品阶 tier（凡/灵/宝/玄/地/天/仙）

- 功法另有**品阶 tier**（`skills.js`，7 档，`tierCoef` 1.0…10.0），随四界提升、决定碎片种类与强度系数 —— 它是**功法的品级**，不是等级。
- 与物品品级为不同领域的两套成色名，二者不混用、不互相称“等级”。

## 6. 验收要点

1. 全游戏截图/文案检索不到面向玩家的「等级 / Lv / X 级」。
2. 主角/灵兽/NPC/敌人均以 19 大境×九重×四阶（gl1–684）呈现，`realmInfo` 可解析；灵兽不超主角 gl。
3. 数值成长走压缩阶 scaleLevel（1–171），与旧刻度等价、无 NaN（筑基已校正）。
4. 四界天花板：凡 252 / 灵 360 / 仙 576 / 道 684；跨界走通关接引，道界须地狱仙界+道之钥匙。
5. 功法显示「X重·初期/中期/后期/巅峰」，九重巅峰封顶；物品/装备/丹药品级落 11 档（道级预留）。
