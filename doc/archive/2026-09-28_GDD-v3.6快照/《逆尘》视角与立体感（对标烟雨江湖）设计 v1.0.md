> 回答用户的问题：「是我们的视角有问题吗？烟雨江湖怎么看起来好像更加立体，想想是怎么实现和设计的？」

---

# 1. 结论先行

> **不是"我们的视角错了"，而是"投影方式不同"。**
> 《烟雨江湖》用的是 **斜俯视（oblique / 2.5D）**，我们用的是 **正俯视（top-down orthographic）**。
> 两者都能成立，但**"立体感"来自四个可叠加的视觉线索**，我们目前一个都没用满。

---

# 2. 两种投影的差别

| | **正俯视（我们）** | **斜俯视（烟雨江湖）** |
|---|---|---|
| 摄像机 | 正上方垂直向下 | 约 **50~60° 俯角**（斜上方） |
| 建筑 | 只看得到**屋顶** | 看得到**屋顶 + 一面侧墙** |
| 树 | 一个圆冠 | 圆冠 + **可见的树干高度** |
| 地面 | 完全平铺，格子感强 | 有**近大远小的轻微透视**，道路有宽度感 |
| 人的观感 | "看地图" | "看街景" |
| 实现成本 | 低（一张俯视贴图即可） | 高（每件素材要画**顶面 + 侧面**两张） |

**关键洞察**：斜俯视的立体感**不来自透视计算**（2D 游戏根本没有真透视），
而来自**美术上把"高度"画出来**。也就是说 —— **这是画法问题，不是引擎问题**。

---

# 3. 立体感的四个线索（可叠加，按性价比排序）

## 3.1 接触阴影（Contact Shadow）—— 最便宜、最有效

**做法**：每个立在**地面上的物件**（树/石/建筑/角色/NPC）脚下画一个**椭圆暗影**。

**为什么有效**：阴影是大脑判断"这个东西是浮在地上还是贴在地上"的**第一线索**。
没有阴影的物件看起来像"贴纸"；有阴影就像"立着的"。

**我们现在的状态**：只有主角有影子，**装饰物一个都没有** —— 这是最该补的一条。

## 3.2 高度偏移（Vertical Offset）—— 第二便宜

**做法**：高物件绘制时**向上偏移 `h` 像素**（`h` = 它在俯视图里的"视高"），
同时它脚下那一格仍然占地 —— 于是玩家读出"这个东西有高度"。

**关键**：偏移量要与 y 排序配合（`sortY = 物件底部`），否则会穿模。

## 3.3 双面绘制（顶面 + 侧面）—— 要出图

**做法**：建筑/树木画两张：
- **顶面**（从正上方看）：屋顶瓦片
- **侧面**（从斜前方看）：墙面 + 门窗

绘制时先画侧面（偏下），再画顶面（偏上），两者在**同一条"屋脊线"上接缝**。

**成本**：每件素材多一张图；但**这是斜俯视观感的来源**。
我们已有 35 栋建筑素材（`struct.<bk>`），可以在现有图的基础上**程序化补一条侧墙**
（沿建筑底边向下延伸 N 像素 + 加深色 + 画几道窗），**不用重出图**。

## 3.4 地面层次（Ground Layering）—— 已有基础

**做法**：地面不是一个平色，而是**分层叠加**：
底层土色 → 草地/石路贴图 → **道路边缘描边** → 阴影区（建筑/树的投影）→ 高光（受光面）。

**我们现在的状态**：已有 `ground.<区域id>` 贴图 + 区域调色板；
**缺"物件投影到地面"这一层**（把树/建筑的影子画到地面上）。

---

# 4. 我们该怎么做（分三步）

| 步 | 内容 | 出图 | 影响 |
|---|---|---|---|
| **A** | **接触阴影铺到所有装饰物**（树/石/井/围栏）+ 建筑底部加一条暗边 | 无 | 立刻"贴纸 → 立着" |
| **B** | **高度偏移**：树向上偏 6~10px，脚下占格不变；y 排序用底部 | 无 | 树"长高了" |
| **C** | **建筑程序化补侧墙**（沿底边向下延伸 + 深色 + 窗） | 无 | 建筑"有厚度了" |
| D | 重出**顶面/侧面分离**的建筑素材 | 有（35 栋） | 真正的斜俯视 |

> **A+B+C 全部零出图**，且能拿到 80% 的"立体感"收益。D 是后续优化。

---

# 5. 不改的东西（避免踩坑）

| 项 | 为什么不动 |
|---|---|
| **逻辑坐标仍是 16px 格** | 玩法、寻路、地图生成全建立在格上；改投影等于重做 |
| **y 排序规则** | 已经正确（按物件底部排），是斜俯视的必要条件 |
| **碰撞与通行** | 与视觉解耦 —— 视觉"高"不影响逻辑"占一格" |
| **区域调色板** | 与投影无关，保持 |

> ⚠️ **最大的坑**：一旦引入"高度偏移"，**所有命中判定（点地寻路、点物件交互）
> 仍必须按格坐标算**，不能按屏幕像素 —— 否则点击会偏。
> 项目已有 `save.pos` 是格坐标的纪律（HANDOVER §5），这条要继续守。

---

# 6. 与"动效"的关系

立体感与动效是**两件事**，但互相放大：

- 立体感解决"这是不是一个有厚度的世界"
- 动效解决"这个世界是不是活的"

我们已经做了动效（行走/树摇/粒子/天劫），**立体感是目前更短的那块板**。
A+B+C 做完之后，配合已有的接触阴影缩放（走路时影子变小），
观感会从"平面地图 + 会动的小人"变成"有厚度的场景 + 会动的小人"。
