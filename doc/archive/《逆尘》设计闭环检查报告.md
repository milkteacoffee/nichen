## 原始冲突记录

你新提的横屏、APK、画质目标，与 GDD 现有表述存在直接冲突，必须先裁决：

| # | 冲突点 | 现状 | 需要裁决 |
|---|---|---|---|
| C1 | **横屏 vs 竖屏** | GDD 明确写"竖屏回合制"，全部 UI 想象基于竖屏 | 改为横屏后：战斗是否改为"敌方在左/我方在右"？地图视野比例、菜单排布需全部重写。需出横屏 UI 线框稿 |
| C2 | **"免安装 APK"语义矛盾** | APK 本身就是必须安装的安装包；真正免安装的是 PWA/网页 | 三选一：① 标准 APK（Capacitor 打包，可侧载、免应用商店、但仍需安装）；② PWA（浏览器打开、加到桌面、真正免安装，离线靠 Service Worker，iOS 限制多）；③ 两者都要。**建议：Capacitor 打 APK 为主、PWA 为副** |
| C3 | **画质参照自相矛盾** | GDD 定位"2D 像素"；《烟雨江湖》是**高清手绘国风 2D（非像素）**；《宝可梦》像素作是 GBA/NDS 级，Switch 作是 3D | 需明确美术风格：A. 纯像素（对标 GBA 宝可梦，定义瓦片/精灵原生分辨率）；B. 手绘国风（对标烟雨江湖，工作量与像素完全不同）；C. 混合（像素场景 + 手绘立绘，独立游戏常用）。**不裁决此项，技术栈与资产清单都无法定** |
| C4 | 技术栈未定 | 文档未指定引擎 | HTML5 原生（我可直接交付、可打 APK）/ Godot / Unity。画质目标越高、资产越多，引擎选择影响越大 |
| C5 | 目标机型/性能指标缺失 | 无 | 最低安卓/iOS 版本、内存、帧率目标（60fps？）；你说不在意包体，但仍需确认是否接受单包 1GB+ |

# 二、战斗系统缺口【P0 阻断最密集区】

## 2.1 基础数值公式缺口

| # | 缺口 | 说明 / 建议 |
|---|---|---|
| B1 | **速度（SPD）公式未定义** | 战斗核心机制是"按速度排序行动"，但成长规格只给了攻/防/生命。【建议】主角 SPD = 10 + 全局等级×0.5 + 饰品速度；御兽用各自种族基础值+成长；麻痹 ×0.7 |
| B2 | **防御→减伤映射未定义** | 伤害公式含"(1−减伤)"，走算固定用 20%，但没给函数。【建议】减伤 = DEF ÷ (DEF + 100)，上限 70%（DEF=25 时恰为 20%，与走算吻合） |
| B3 | **技能战斗内消耗未定义** | "灵力值"是功法经验，不是蓝条。功法技能在战斗里靠什么限制？【建议】P0 用**冷却制**：普攻无冷却，技能各自 2-4 回合冷却，不设蓝条（与法宝冷却统一管理） |
| B4 | 命中/闪避/暴击未定义 | 只有普攻对站位 70%/30%。技能命中率？有没有闪避属性、暴击（1.5 倍？）？【建议】技能默认 95-100% 命中、无闪避属性、暴击率 5%/暴伤 1.5×，由技能/饰品修正 |
| B5 | 取整与最小伤害 | 【建议】伤害向下取整、最小 1 点；±5% 随机浮动 |
| B6 | 治疗公式 | 治疗量吃什么属性？【建议】治疗技能 = 施法者攻击 × 技能倍率（医者也堆攻）；丹药按最大生命百分比 |

## 2.2 指令集缺口

| # | 缺口 | 说明 / 建议 |
|---|---|---|
| B7 | **没有"逃跑"指令** | 指令集为攻击/功法/道具/防御/切换/收服，无逃跑。野外能否逃？Boss 呢？【建议】野外可逃跑，成功率 = 我方存活均速 ÷ (我方均速+敌方均速)，失败浪费本回合；Boss/剧情战禁用逃跑 |
| B8 | 切换御兽规则 | 消耗回合吗？一回合几次？兽倒下后是自动弹窗还是等主角指令？【建议】切换消耗行动单位本回合；御兽倒下不自动打断，在主角或该兽下一次行动时提示；每场战斗每只御兽只能上场一次（防止反复横跳） |
| B9 | 道具使用规则 | 一回合只能用 1 个？能否对敌方用（收服除外）？【建议】是；道具可指定我方目标，敌方只能丢妖囊 |
| B10 | 收服失败后果 | 妖囊必消耗？占用整回合？能否连续收服？【建议】妖囊必消耗、占用行动、可连续尝试；收服率封顶 95%、保底 1% |
| B11 | 法宝主动技谁能用 | 只有主角？御兽装备的妖兵有主动技吗？【建议】P0 法宝主动技仅主角施放；妖兵只给属性/被动 |
| B12 | 主角倒下能否救 | 主角死亡立即判败，还是御兽可以用还魂丹拉起来？【建议】立即判败（规则已写"主角倒下即败北"，需明确无复活手段） |
| B13 | 自动战斗/倍速 | 刷怪体验常用，是否做？【建议】P0 加 2 倍速开关，自动战斗可列后续 |

## 2.3 状态系统缺口

| # | 缺口 | 说明 / 建议 |
|---|---|---|
| B14 | **睡眠状态缺失** | 收服率表格用了"睡眠 ×1.5"，但战斗状态表只有中毒/灼烧/麻痹/封印。需补睡眠定义（无法行动、受击醒来、谁的技能能施加）【建议】树精 L5 技能"催眠粉" |
| B15 | 状态持续回合数 | 全部没写。【建议】中毒/灼烧/麻痹/封印持续 3 回合，睡眠持续 1-2 回合；DOT 在该单位行动开始时结算 |
| B16 | 状态共存与叠加 | 能否同时中多种？同类刷新还是叠加？【建议】可同时存在，同类刷新时长不叠加；每回合最多新附加 1 种 |
| B17 | 施加概率与抗性 | 技能附带状态的概率需逐个写；有没有抗性（等级差）？【建议】技能自带概率（25-60%），目标等级高于施法者 5 级以上概率减半 |
| B18 | 灼烧"当前生命 8%"不会致死 | 当前生命百分比 DOT 数学上永远打不死人；中毒（最大生命 5%）可以。是否为有意设计？【建议】灼烧伤害不致死（保底 1 血），中毒可致死，写明 |
| B19 | 封印描述歧义 | "本回合无法使用功法"是仅当回合还是持续 N 回合？【建议】持续 2 回合，可被解封符清除 |
| B20 | 状态与收服系数对照 | 麻痹 1.3、睡眠 1.5 已知；中毒/灼烧/封印/无状态系数缺失。【建议】无状态 1.0、中毒 1.1、灼烧 1.1、封印 1.2、麻痹 1.3、睡眠 1.5，取当前最高系数 |

## 2.4 蓄力预告（设计支柱"危险必须先可读"）

| # | 缺口 | 说明 / 建议 |
|---|---|---|
| B21 | 哪些技能必须预告 | 【建议】倍率 ≥1.5 的单体大招、全体攻击、即死类必须提前 1 回合预告；普通技能不需要 |
| B22 | 预告的表现形式 | 需定义：横幅文字 + 单位身上"蓄力中"特效 + 目标是否明示（建议明示技能名与目标排） |

| B24 | 预告后玩家的反制手段 | 防御（−50%）、切换、属性克制反杀——教学需点明 |

# 四、御兽系统缺口

| P4 | 初始御兽来源未定 | 走查里青纹蛇开局就在，但获取方式没写。【建议】剧情：炼气后阿桂/沈伯赠送一只 L3 青纹蛇 |

| P9 | 羁绊数值化 | 羁绊如何增长、上限多少、合体技效果？【建议】羁绊 0-100，喂养/出战各加，100 解锁合体技（P0 可只做 1 个合体技或列后续） |
