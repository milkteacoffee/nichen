# 4. 冲突时的权威顺序

```
1. 代码（www/，尤其 www/assets/README.md 技术手册）
2. HANDOVER.md（项目交接/开工手册）
3. 本文件（设计文档总索引与版本基线 v3.3）
4. 现行专题稿（领域就近 + 版本新旧）：
   副本Boss形象与关卡结构 v3.3 ＞ 闭环报告 v3.2 ＞ 境界体系 v3.2 ＞ 副本系统 v3.2 ＞ v2.7 ＞ v2.6 ＞ v2.5 ＞ v2.4 ＞ v2.3 ＞ v2.2 ＞ v2.1 ＞ v2.0

6. 历史快照：v0.9 ＞ v0.8 ＞ … ＞ v0.1 ＞ 无编号稿（仅作背景，不裁定当前实现）
```

| 口径 | 说明 |
|---|---|
| 领域优先 | 该领域专题稿优先于更高编号但不相关的稿子 |
| 代码为准 | 设计稿与运行代码冲突以代码/README 为准，再回改设计稿 |
| 已删除内容 | 六维（v0.1 角色成长）、幼年事件卡（v0.6）已删除，旧稿再提及无效 |

# 6. 命名与升版规则（必须遵守）

## 6.1 文档文首统一头（每份 md 都要有）

```
> 【统一设计基线】GDD vX.X（日期）｜ 全案版本统一管理，单份文档不再单独代表“最新”
> 【文档状态】现行有效 / 历史快照
> 【权威依据】文档间冲突时，以《设计文档总索引与版本基线 vX.X》给出的权威顺序为准
```

## 6.2 升版规则

1. **全案共享一个基线版本号**：任何专题稿有实质变更，基线 +0.1，**所有文档文首戳同步更新**。
2. 不再出现“只有一两份文档是新的、其余还是旧号”。
3. 文档标题历史编号（v2.x、v0.x）可保留，**是否现行以本索引第 2/3 节和文首状态行为准**。
4. 新增文档：先在本索引第 2 节登记，再写正文并带统一头。
5. 废弃文档：不删除，移入第 3 节“历史快照”、状态改“历史快照”；
   同日被取代、尚无历史价值的草稿可直接替换（如 v3.1 → v3.2）。

## 6.3 文件命名

- 格式：`《逆尘》{主题} v{编号}.md`；无编号历史稿维持原名并在本索引注明。
- 代码版本以 `www/assets/README.md` 与构建产物为准，与设计基线号分别维护。
