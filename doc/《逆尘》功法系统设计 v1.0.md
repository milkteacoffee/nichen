## 1. 设计口径（用户逐字锁定，最高优先级）

> 「最多激发一本功法，可以走收集流，然后一个功法根据等级存在一个主动和一个被动或者没有主动技能，只有被动技能，功法品级越高，主动技能越多，最多三个主动，一个功法最多只有五个技能。」

三条核心取舍：

1. **同时只能「激发/装备」一本功法**——但可以**收集多本、按需切换（收集流）**。
2. **深度在功法内部**：一本功法随**修炼等级（功法自身的重/阶）**逐步解锁招式，而不是靠同时装多本叠数值。
3. **一本功法最多 5 个招式、其中最多 3 个主动**；品级越高主动越多。低级功法可能只有「1 主动 + 1 被动」，甚至「纯被动」。

设计意图：

- 杜绝旧模型"全学满、全装上 → 功法数值压过境界"的崩坏（旧版实测全学满 ATK +34225%）。
- 让"选哪一本、何时切换"成为真正的构筑决策；收集多本是为了应对不同局面（爆发/续航/群攻/御兽）。
- 高品功法的价值 = **更多主动招式 + 更高品阶系数**，且高品功法"难得难练"。

## 2. 单本激发与收集流

- **激发槽 = 1（指功法"本数"，不是招式数）**：`Player.ACTIVE_SLOTS = 1`。
- `Player.activateSkill(save, id)` 为**切换语义**：
  - 激发新功法即**替换**当前功法（先卸旧本、再激新本）；
  - 只校验：未习得 / 已被废功（`voided`）/ 重复激发同本（返回"该功法已在激发位"）；
  - 不再被"槽满"挡住。
- `Player.cancelSkill(save, id)`：卸下当前激发功法；卸下后激发位为空。
- `Player.autoEquip(save)`：**仅当没有主修功法时**自动激发一本，不会自动顶掉玩家手动选择的功法。
- 存档字段 `save.skillEquip` 为数组、长度 ≤ 1（只取 `[0]`）。旧档（多装时代）可直接运行，无需强制迁移。
- **未激发时的兜底**：战斗/属性自动取"等级最高的可用主动功法" `Player.defaultSkillId(save)`，保证玩家不会因没激发而零技能。

> 收集流体验：储物/功法面板里可看到所有已学功法；每本可查看招式与属性，点「切换激发」即可换主修。未激发的功法**不叠加任何面板属性**。

## 3. 功法容器与招式（moves）

### 3.1 数据结构

- 一本功法是一个**容器**，含 `moves[]`；每个招式（move）字段：

  | 字段 | 含义 |
  |---|---|
  | `n` | 招式名（中文，**禁止裸 ID**） |
  | `kind` | 攻击 / 防御 / 仙术 |
  | `active` / `passive` | 主动 / 被动标记 |
  | `elem` | 元素：金/木/水/火/土/光/雷/风/暗/无 |
  | `mult` | 伤害/治疗倍率（主动） |
  | `cd` `hit` `target` `hits` `status` `pierce` `heal` | 冷却/命中/目标/多段/异常/穿透/治疗（主动） |
  | `unlock` | **解锁所需的功法修炼等级（1..36）**，必须非递减 |

- 约束（由 `skill.activate.contract` 钉死）：
  - `moves.length ≤ 5`；其中主动招式 `≤ 3`；
  - `unlock ∈ 1..36` 且**非递减**；
  - 每本功法至少有 1 个招式。
- 主动判定 `isActiveMove(m) = !!m.active || (m.kind==='攻击' && !m.passive)`——**必须排除被动**，否则攻击功法的"被动本体"会被误当主动（曾出现同一招显示两次）。

### 3.2 两个样板

- **入门《引气诀》（凡品）= 1 主动 + 1 被动**，皆 `unlock:1`：
  - 主动「引气诀」：`mult 1.05`（威力刻意极小）；
  - 被动「粗浅吐纳」：仙术系，给少量气血/法力。
- **高阶《烈焰诀》（凡品深度示范）= 3 主动 + 2 被动（共 5）**，解锁阈值 **1 / 9 / 18 / 27 / 36**：

  | unlock | 招式 | 类型 |
  |---|---|---|
  | 1 | 烈焰诀（mult1.6，单体，可灼烧） | 主动 |
  | 9 | 火灵 | 被动 |
  | 18 | 烈焰冲击（mult2.0，单体） | 主动 |
  | 27 | 焚意 | 被动 |
  | 36 | 焚天（mult2.8，全体，高灼烧） | 主动 |

### 3.3 旧功法自动封装（legacyMoves）

未显式给 `moves` 的旧式单招功法，由 `legacyMoves(sd)` 自动封装，**不破坏旧内容**：

- 攻击功法（有 `mult`）→ **1 主动（原招式）+ 1 被动（功法本体，贡献 ATK）**；
- 纯被动功法 → **1 被动**；
- 带 `active` 治疗的功法 → **1 被动（本体）+ 1 主动（治疗招式）**。

## 4. 功法修炼等级与品级（无"等级"概念）

- **功法修炼等级 prog = 1..36**（`SKILL_MAX_PROG=36`），对应**九重 × 四小阶**：

  | prog | 修炼境界（功法自身） |
  |---|---|
  | 1–4 | 一重·初期 / 中期 / 后期 / 巅峰 |
  | 5–8 | 二重·初期 … 巅峰 |
  | … | … |
  | 33–36 | 九重·初期 / 中期 / 后期 / **巅峰（最高）** |

- **界面禁止出现"等级 / Lv / 裸数字"**：功法进度一律显示为"X 重·初/中/后/巅峰"；招式解锁条件显示为该招式所需的**功法境界名**（未解锁时置灰，如"锁·烈焰冲击（五重初期）"）。
- **功法品级 `tier`** 与物品品级体系一致，品阶系数 `tierCoef`：

  | tier | 凡 | 灵 | 宝 | 玄 | 地 | 天 | 仙 |
  |---|---|---|---|---|---|---|---|
  | 系数 | 1.0 | 1.5 | 2.0 | 3.0 | 4.5 | 6.5 | 10.0 |

- 功法修炼消耗"灵力（po）"，**品级越高、修炼等级越高，消耗越大**（"难得难练"：凡阶 1→36 总灵力 ≥ 30000）。
- 功法里程碑（`getMilestones`，随主修功法生效）：在特定修炼等级给额外效果（倍率/暴击/穿透/吸血/属性百分比），与招式解锁叠加。

## 5. 招式如何进战斗与面板

### 5.1 主动招式 → 战斗技能栏

- 战斗技能栏只取**当前激发功法**（未激发则 `defaultSkillId` 兜底）的 `activeMovesOf(gfId, lv)`；
- 每个已解锁主动招式编译成**自包含条目**（施放直接读条目字段，不回查功法表）：
  - **单主动**招式：条目 id 用**功法名**；
  - **多主动**招式：条目 id 用 `功法名@i`；
  - 无任何主动招式时兜底「凝气拳」（不耗法力）。
- 法力消耗 `Player.manaCost(sd, lv) = round((10 + (lv-1)*4) × tierCoef[tier])`：
  - 最低 10 点、功法修炼越高耗越多、再乘品阶系数；
  - 法力不足 → 招式禁用并给出原因（sub 文案），每回合回复 `MP_REGEN = 5`。
- **未激发功法的主动招式不会进战斗栏。**

### 5.2 被动招式 → 面板属性（computeStats）

- `computeStats` 只取当前激发功法已解锁的**被动招式**（最多 2、天然有界）：

  ```
  贡献 = sqrt(功法lv) × tierCoef[功法tier] × 灵根匹配
  · 攻击系被动 → ATK += sqrt(lv) × 3 × m
  · 防御系被动 → DEF += sqrt(lv) × 2 × m
  · 仙术系被动 → HP  += sqrt(lv) × 9 × m；MP += sqrt(lv) × 3 × m
  ```

- `m` 含品阶系数与灵根匹配（元素匹配灵根 ×1.2）；
- 用 **`sqrt(lv)` 边际递减**：保证 lv1→36 仍看得出成长（约 6 倍），但**单本满级功法不会碾压同境界对手**——契约红线：单本满级 ATK 增幅 **≤ 200% 且 ≥ 20%**；
- **收集多本但未激发的功法不叠加任何属性。**

### 5.3 功法面板（panels.js）

- 功法详情：标题行左侧画属性徽记 `skill.<拼音>`；
- 「效果」段改为**两列招式**：左列主动、右列被动；行距 12；未解锁招式置灰并显示"锁·名（解锁境界）"；
- 激发按钮：未激时「激发」、已激另一本时「切换激发」；
- 「参悟 / 精进」按钮读碎片与灵力口径。

## 6. 功法获取途径

> 用户口径：功法通过**完成任务、刷野怪、副本、小世界探索、碎片参悟**获得；主角轮回转世**不带功法**。

| 途径 | 说明 |
|---|---|
| **任务** | 散修任务 / 宗门任务奖励；新手 m0-1 由沈伯**授予一本《引气诀》**。 |
| **野怪（刷野）** | 战斗胜利给灵气/灵力/灵石；**功法碎片按 2.5% 几率掉落**（品阶按当前所在界）。 |
| **副本** | 副本通关 / Boss 给功法或碎片（副本碎片 3–5、小 Boss 1–2、刷减半）。 |
| **小世界 / 秘境探索** | 探索宝箱、事件给功法（高品功法主要来源）。 |
| **碎片参悟** | 集满 **10 片同品阶碎片** → 随机一本该品阶功法（`Player.inscribe`）：未习得 → 习得 lv1 并自动激发；已习得 → +1 级。 |

- 碎片按品阶：凡品 / 灵品 / 宝品功法碎片；`shardPool(tier)` **现算**（加新功法无需改表），该品阶无功法时向下退一档。
- **宗门功法（`src='sect'`）不进碎片池**：散修无法用碎片参悟出宗门功法；宗门功法只走宗门途径（拜师/贡献/传承）。
- 功法归属 `src`：`common`（两道通用）/ `free`（散修流通）/ `sect`（宗门专属），新增功法必须显式声明，否则兜底为 `free`。

## 7. 破境与功法的关系

- 破境沿用**进度条累积模型**（与功法解耦，但同属成长闭环）：
  - 每次尝试**耗 1 颗破境丹**；
  - 进度 <100 → 失败：**进度 +50%（封顶 100）、当前气血减半**；
  - 进度 ≥100 → **必定成功**：清进度/失败数，再按 `TRIB_CHANCE=0.5` 掷是否历天劫。
  - 即**最多失败两次，第三次必成**。
- **「静心阵」在进度模型下的新职责**：不再加"成功率"，而是**减轻失败气血反噬**——有静心阵时失败保留 **75%** 气血（默认 50%）。
- 天劫镜像战：面板逐项等于主角、出招随机、功法取主角已学且按九重满级编译（详见归档战斗/天劫设计）。

## 8. 数据 / API 清单（开发对照）

**`data/skills.js`（挂到 `G.Data`）**

- 数据：`skills`（功法容器表）、`tierCoef`、`shardByTier`、`shardCost=10`、`tierByWorld`、`SKILL_MAX_PROG=36`、`MILESTONES=[9,18,27,36]`。
- API：
  - `gongfaMoves(id)`：取功法招式（显式 moves 或 legacy 封装）；
  - `unlockedMoves(id, lv)`：已解锁招式；
  - `activeMovesOf(id, lv)` / `passiveMovesOf(id, lv)`：已解锁主动 / 被动；
  - `getMilestones(skillData)`：里程碑模板；
  - 常量 `MAX_MOVES=5`、`MAX_ACTIVE_MOVES=3`。

**`core/player.js`**

- `ACTIVE_SLOTS=1`、`activateSkill`（切换）、`cancelSkill`、`autoEquip`、`equippedIds`（滤废功）、`defaultSkillId`；
- `computeStats`（被动招式 sqrt 贡献）、`manaCost`、`MP_REGEN=5`；
- `startBigBreak`（进度条破境）、`breakChance`（进度显示）、`TRIB_CHANCE=0.5`、`inscribe`（碎片参悟）。

**场景 / 面板**

- `scenes/battle.js`：技能栏读 `activeMovesOf`、单/多主动 id 规则、兜底凝气拳；
- `core/panels.js`：两列招式、切换激发、属性徽记；
- `scenes/town.js`：新手 m0-1 只授一本《引气诀》。
