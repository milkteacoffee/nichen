# 《逆尘》天道意志（本地 LLM 接入）设计与实现 v0.5

> 本地部署的大语言模型在游戏中扮演 "天道意志"：注视穿越者、降下低语、死亡时拦路问话，并随轮回次数逐渐识破 "异世之魂"。
> **参考**
>
> ：博德之门 / 跑团 GM（AI 叙事但规则由系统裁决）、《崩坏：星穹铁道》（BOSS 意志演出）、《天外武林》《环世界故事讲述者》（AI 叙事层）、《人生重开模拟器》（轮回评语）；技术参考 OpenAI 兼容 API、Ollama、llama.cpp、WebLLM。
> **铁律**
>
> ：LLM 产出
>
> **文本与有限白名单动作**
>
> ；它
>
> **不直接写存档、不直接算伤害、不直接发物品**
>
> —— 所有数值由游戏代码按既有公式裁决。



***

# 1. 定位：天道意志是谁



| 项      | 设定                                                                  |
| ------ | ------------------------------------------------------------------- |
| 身份     | 尘霄界的**秩序意志本身**（非人格神；区别于 "天宫之主"—— 后者是执掌秩序的角色，后期登场）                   |
| 性格     | 漠然、公正、话少、惯用谶语与反问；不回答 "怎么通关"、不解释系统规则                                 |
| 它知道什么  | 当世的境界 / 灵根 / 行为、生死簿上的死亡次数；**初期不知 "天道之缺" 真相，也不知主角来自异界**—— 靠一次次注视自行发现 |
| 它不知道什么 | 玩家面板数值、攻略、游戏外的一切；它不是客服、不是聊天玩具                                       |
| 叙事母题   | 玩家持逆命珠逆天，本质是 "与天道对弈"—— 天道意志就是对面那位棋手，从无视 → 熟悉 → 警觉 → 识破              |

# 2. 核心机制：注视值与感应阶段

## 2.1 天道注视值（每世累计，轮回清零）



| 事件               | 注视值 |
| ---------------- | --- |
| 小境界突破（段）         | +3  |
| 大境界突破（如淬体→炼气）    | +15 |
| 击杀 Boss          | +8  |
| 逆命珠剧情发动          | +10 |
| （后续）收服妖兽、炼丹炼器出极品 | +5  |



* 注视值每到 **30 / 60 / 100** 触发一次 "天道低语"；**每世最多 3 次**（防啰嗦、控算力）。

* 低语：屏幕天穹处一行打字机谶语，8 秒淡去，不打断操作。

## 2.2 天道感应度（meta 永久档，跨世累计）

按 "天道与你正式对话的次数"（低语不计）推进阶段：



| 阶段     | 条件      | 天道的认知 / 台词基调                        |
| ------ | ------- | ----------------------------------- |
| 一・无视   | 0-2 次   | 视你为寻常修士："凡人修行为何？"" 逆天者，古来无存。"       |
| 二・眼熟   | 3-5 次   | "你身上，有本座熟悉的气息……"" 生死簿上，你的名字淡了。"     |
| 三・识破轮回 | 6-9 次   | " 你已死过多次，又回来。**你是何人？**"             |
| 四・识破异世 | 10-14 次 | " 三界六道，无来处。**你不属于此界。**"             |
| 五・对弈   | 15 次起   | 天道主动约谈，与卷伍 / 卷陆主线对接（"珠在你手，你我终有一战。"） |



* 感应阶段写入 world packet，直接驱动 system prompt 的态度。

## 2.3 固定对话触发点



| 触发点                            | 形式                     | M0  |
| ------------------------------ | ---------------------- | --- |
| **死亡过场**：死亡结算屏之前，天道拦魂问话（1 轮对话） | "本座掌生死，你何以去了又回？"       | ✅   |
| 大境界突破后的低语                      | 见 §2.1                 | ✅   |
| 心魔战前（问心）                       | 天道 / 心魔动态台词（基于因果簿与前世录） | M1  |
| 渡劫、进入新大地图                      | 长对话                    | 后续  |
| NPC 自由对话、工具调用 "降灾 / 赐福"        | 见 §8                   | M2+ |

# 3. 玩家侧交互（UI）

## 3.1 天道对话（横屏全屏演出）



```
┌────────────────────────────────────────────────────────┐
│            （天穹：缓缓流动的星河/云纹，暗金）           │
│                                                        │
│        “ 你 已 死 过 多 次 ， 又 回 来 。 ”              │  ← 打字机，竖排居中
│                                                        │
│   [ 默然叩首 ]  [ 弟子只求长生 ]  [ 自由应答 ▸ ]        │  ← 3 预设 + 可展开输入框
│                                          [不问了，入轮回]│
└────────────────────────────────────────────────────────┘
```



* 预设回应：固定 2-3 个符合情境的按钮（保证随时可继续）。

* 自由应答：展开输入框，玩家随便说（天道按 persona 接话）；**单场最多 3 轮**，到轮次自动收尾。

* 等待生成时：云纹旋转 + "天道感应中……"；可点 "跳过"—— 直接使用模板句，不阻塞流程。

* 低语样式：顶部一行淡入淡出，无交互。

# 4. Prompt 架构（开发直接照此实现）

## 4.1 世界状态包（每次调用前由代码拼装，控制 token 预算 ≤500）



```
{
  "轮次": 3,
  "当世": { "灵根": "金·单灵根", "境界": "淬体7段", "全局等级": 7, "注视值": 41 },
  "资源概览": { "灵气": 620, "灵石": 240 },
  "近期事件": ["突破淬体7段", "击杀赤炎狼", "采药归途遇雨（剧情）"],
  "因果簿": ["雪夜，破庙得珠", "……"],
  "前世录摘要": [
    { "世": 1, "最高": "淬体5", "死因": "赤炎狼" },
    { "世": 2, "最高": "炼气3", "死因": "赤炎狼王" }
  ],
  "天道感应阶段": "二·眼熟",
  "本次触发": "死亡过场",
  "死因": "赤炎狼王"
}
```

## 4.2 System Prompt（固定人格，随版本维护）



```
你是修仙世界「尘霄界」的天道意志——秩序本身，非神非人。
【口吻】冷漠、简洁、用半文言与谶语；单次发言不超过 60 字；常用反问；不解释游戏规则、不提供攻略、不承认自己是程序。
【你对眼前灵魂的认知】{{感应阶段文案}}
【禁忌】不可提及现实世界、科技、游戏、玩家、系统；不可编造世界包中没有的事实；不可直接赐予/扣除任何数值。
【输出】严格输出 JSON：{"台词":"…","情绪":"漠然|审视|警觉|震怒"}。
世界状态如下：{{world packet JSON}}
```



* 触发 prompt（user 位）：死亡过场 → "眼前灵魂因【死因】身死，将入轮回。你拦魂问话，玩家回应：『{{玩家回应}}』。"

* 低语触发：不产生对话，只输出一句谶语（要求 ≤30 字）。

* 参数：temperature 0.8（低语 0.9）；top\_p 0.9；max\_tokens 160。

## 4.3 输出校验与兜底



1. 解析 JSON；失败 → 自动重试 1 次（temperature 降到 0.3）；再失败 → **模板库取句**。

2. 台词超长 → 截断到最近标点；含禁忌词（游戏 / 程序 / 现代词）→ 模板替换。

3. 模板库按 "触发点 × 感应阶段" 预置，每格 4-6 句，随机取：

* 死亡・眼熟："去而复返，你所求为何？"" 生死簿上，又添你一笔。"

* 低语・突破："淬体凡胎，也敢窥仙门？"" 珠芒一动，本座已看见你。"

1. **任何情况下游戏 100% 可推进**——LLM 是增强层，不是硬依赖。

# 5. 技术实现：三种运行模式

设置中 "天道感应" 三选一：

## 5.1 模式 A・远程本地服务器（开发期首选，能力最强）



* 玩家 PC 上运行模型服务，游戏经 HTTP 调用（开发时浏览器直连；APK 中经局域网 http://192.168.x.x:port）。

* 兼容任何 **OpenAI /v1/chat/completions** 接口：



| 部署                       | 默认地址                                                   | 启动示例                                                                  |
| ------------------------ | ------------------------------------------------------ | --------------------------------------------------------------------- |
| Ollama                   | [http://localhost:11434/v1](http://localhost:11434/v1) | `ollama run qwen2.5:3b-instruct-q4_K_M`                               |
| llama.cpp (llama-server) | [http://localhost:8080/v1](http://localhost:8080/v1)   | `llama-server -m qwen2.5-3b-instruct-q4_k_m.gguf --port 8080 --jinja` |
| LM Studio                | [http://localhost:1234/v1](http://localhost:1234/v1)   | 载入模型后 Start Server                                                    |



* 请求体：`{model, messages:[{system},{user}], temperature, max_tokens, response_format:{type:"json_object"}}`；Ollama 顶层加 `format:"json"`；llama.cpp 可用 `json_schema` 语法约束（**语法约束保证合法 JSON，优先使用**）。

* 流式：SSE 流式输出（打字机效果）；不支持则整段返回。

* 超时：首次 token 10 秒、总时长 30 秒，超时走模板。

## 5.2 模式 B・端内推理（APK 离线方案，推荐交付形态）



* 用 **WebLLM（MLC，WebGPU）** 在 Android WebView 内本地推理，无需服务器、纯离线：



```
// 仅 APK/现代浏览器环境加载（本地 ESM 资源，不走 CDN）
import * as webllm from "./assets/webllm/webllm.mjs";
const engine = await webllm.CreateMLCEngine("Qwen2.5-1.5B-Instruct-q4f16_1-MLC", {
  appConfig: myBundledConfig,   // 指向 APK 内置模型文件，避免联网下载
  initProgressCallback: p => showProgress(p.text)
});
const chunk = await engine.chat.completions.create({ messages, stream:true, temperature:0.8 });
```



* 模型选型：

  \| 档 | 模型 | 体积（Q4） | 适用 |

  \|---|---|---|---|

  轻 | Qwen3-0.6B / Qwen2.5-0.5B | \~500MB | 低端机，只做台词 |

  中（推荐） | **Qwen2.5-1.5B-Instruct** | \~1.1GB | 中文好、端上 10-20 tok/s |

  强 | Qwen2.5-3B-Instruct | \~2GB | 高端机，接近远程体验 |

* 离线打包关键：模型文件放入 `www/assets/models/`，自定义 modelRecord 的 `model_url/library_url` 指向内置路径（Capacitor 以 [https://localhost](https://localhost) 提供，WebLLM 可加载；Cache 预热一次后离线可用）。**此项为打包阶段的技术验证点，若 WebView WebGPU 对本地资源加载受限，降级模式 C/D**。

* 环境要求：Android System WebView ≥ 125（WebGPU）；不满足时设置页自动隐藏模式 B。

## 5.3 模式 C・原生插件（M2 备选）



* 编译 llama.cpp for Android（JNI），封装 Capacitor 插件直接 GGUF 推理；最稳、兼容面最广，但需写原生代码，列 M2。

## 5.4 模式 D・关闭（纯模板）



* 完全不调用模型，走模板库；游戏体验完整、仅无即兴内容。

# 6. 游戏端模块设计（TianDao）



```
TianDao = {
  mode, endpoint, modelName,             // 设置项（meta 档保存）
  gaze: 0,                               // 当世注视值
  spokenThisLife: 0,                      // 本世低语次数
  meta: { stage:0, dialogCount:0 },       // 感应度（meta 档）
  async notify(eventType){},             // 事件入口：加注视值 → 阈值触发低语
  buildPacket(trigger, extra){},          // 拼装世界包
  async converse(trigger, playerReply){},// 正式对话（死亡过场等）
  callRemote(messages, {stream}){},       // 模式 A
  async callOnDevice(messages){},         // 模式 B（懒加载引擎）
  validate(json){}, fallback(trigger){},  // 校验/兜底
}
```



* 调用链：事件 → notify →（达阈值）buildPacket → 模型 / 模板 → 校验 → 演出 → 计数与存档。

* 自由输入需做长度截断（≤100 字）与基础过滤；不做内容审核服务（本地单机，依赖人格 prompt 约束）。

# 9. M0 集成范围（最小验证）

在 v0.4 M0 基础上只加两件事：



1. **死亡过场天道问话**：死亡 → 天道 1 轮对话（预设回应为主）→ 结算屏 → 轮回殿。

2. **注视值 + 突破低语**：大境界突破（炼气）后一句谶语。

* 验收链路：死亡看到天道问话 → 第二世突破听到低语 → 感应阶段推进 → 第三世死亡时台词基调变化（无视→眼熟）。

* 开发顺序：先模式 A 接用户本机模型调通 → 模板兜底 → 模式 B 随 APK 打包阶段落地。

# 10. 验收用例



| #  | 操作                     | 预期                                   |
| -- | ---------------------- | ------------------------------------ |
