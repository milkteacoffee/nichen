# 《逆尘》Boss 战斗机制与天道心魔对战设计 v1.0

> **定位**：补上设计文档体系里**空缺的一层 —— 战斗内「玩法机制」**。
> **边界（与既有文档不重叠）**：
> - `《副本Boss形象与关卡结构设计 v3.3》` = **形象 + 关卡结构 + 数值成长**（Boss 长什么样、九关怎么排、成长系数）
> - `《天道部署与游戏体现 v2.7》` = **文本 + 部署**（低语怎么写、模型怎么接）
> - **本文 = 机制**（Boss 怎么打、玩家怎么破、天道怎么当对手）。**不重复形象与数值表**。
>
> 本文**只做设计**，不改任何数值、不动平衡。落地按 §5 路线分批。
> 生成日期：2026-09-26 · 基线 v0.11.4

## 0. 问题陈述

鑫总原话两条：

1. **「后期怎么以心魔方式操控心魔和主角战斗，不然一直打人机难度太低了」**
2. **「思考一下游戏里面所有的 Boss 机制，参考一下主流的游戏关卡怎么设计」**

拆成两个真问题：

| # | 问题 | 本质 |
|---|---|---|
| **Q1** | 天道现在只是个**文本生成器**，战斗跟它无关 | 天道"注视"了玩家一辈子，却没有一次真正**出手** |
| **Q2** | 所有 Boss 都是**同一个打法**：血少了就变强 | 20 个 Boss 共用 4 个阶段件（summon/clone/enrage/heal），玩到第 3 个就腻了 |

Q2 比 Q1 更致命 —— **Q1 是"少了个玩法"，Q2 是"玩法本身没层次"**。所以本文**先补机制件（§3），再做天道（§4）**：天道要操控心魔，前提是心魔本身得有可操控的东西。

## 1. 现状盘点（代码事实，非设计意图）

### 1.1 已有的机制件

| 件 | 数据形态 | 落点 | 说明 |
|---|---|---|---|
| **阶段引擎** | `boss.phases = [{ kind, trig, ... }]` | `battle.js: _genericPhases / _runPhase` | `kind` ∈ `summon` / `clone` / `enrage` / `heal` |
| **多段攻击** | `skill.hits` | `battle.js` | 只对单体技生效；各段独立判暴击/克制 |
| **蓄力** | `skill.charge` | `battle.js` | 一回合蓄、下回合放 |
| **群体** | `skill.target: '全体'` | `battle.js` | |
| **吸血** | `skill.vamp` | `battle.js` | 伤害按比例回血 |
| **护盾/治疗技** | `skill.kind: 'shield' \| 'heal'` | `battle.js` | |
| **状态** | `skill.status = { t, chance }` | `battle.js: _applyStatus` | 现有 5 种：`封`(2回合禁功法) / `睡`(1–2) / `麻`(速度×0.7,3) / `毒`(5%上限血) / `烧`(8%当前血) |
| **快照 Boss** | `boss.snapshot: 1.10` | `dungeons.js: DAO_TRIALS 执念化身` | **已经在复刻主角属性** |
| **难度系数** | `DIFF[diff]` + `diffOf(meta, worldId)` | `dungeons.js` | bossHp / bossAtk / trash / cdAdj / dao |

### 1.2 机制件的四个空洞（这就是"打人机"的根因）

**① `trig` 只能按血量 —— 做不出"回合"**
```js
// battle.js:585  —— 唯一判定式
if (boss.hp > 0 && boss.hp <= boss.maxhp * ph.trig) { ... }
```
血量触发意味着：**玩家的操作只会让 Boss 更早/更晚变强，不会改变它做什么**。
→ 打不出"第 5 回合必杀"这种**时限压力**。

**② 召唤物没有机制意义 —— 纯添乱**
`_runPhase` 的 `summon` 只是 `_addEnemy(makeSummon(...))`。召唤物**活着和死了对 Boss 毫无影响**。
→ 玩家学到的唯一应对是"反正都要打死"，**多目标 = 多几下点击**，不是机制。

**③ Boss 属性是死的 —— 没有换招动机**
`boss.elem` 是固定字符串。玩家一旦配好克制属性，**整场不用改**。
→ 灵根/功法的属性系统在 Boss 战里**被浪费了**。

**④ 转阶段没有任何仪式 —— 玩家不知道发生了什么**
`_runPhase` 只有一句 `_log`。血量过线时，玩家正在看别的地方，**机制变化被漏掉**。
→ 预警缺失 = 玩家只能靠"重打一遍"学习。

## 2. Boss 设计模板（强制检查表）

**每个新 Boss 立项时必须填完这 6 条，缺一条不予实现。**

| # | 问题 | 不合格的例子 | 合格的例子 |
|---|---|---|---|
| 1 | **它教什么机制？**（一个 Boss 只教一件事） | "它血厚" | "它教你打召唤物" |
| 2 | **玩家怎么知道？**（预警必须存在） | 无预警，直接秒 | 首回合放一次"教学版"（伤害减半 + 台词） |
| 3 | **玩家怎么应对？**（破法必须可达） | 只能靠等级压制 | 雷属性攻击积破绽 / 清召唤物 / 换属性 |
| 4 | **打不过怎么办？**（兜底） | 卡死 | 可逃 / 降难度 / 换 build 有出路 |
| 5 | **阶段怎么分？**（每阶段必须有**新信息**） | 阶段 2 = 攻击 ×1.3 | 阶段 2 = 换属性 + 解锁新招 |
| 6 | **失败会怎样？**（Fail Forward） | 纯重来 | 推进剧情 / 给情报 / 留标记 |

> 第 5 条最容易违反。**"数值放大"不是阶段，是拖延。** 判定标准：玩家能否用一句话说出阶段 2 和阶段 1 的**打法区别**？说不出就是纯数值。

## 3. 机制件扩展（按实现成本排序）

> 原则：**能在现有 `_genericPhases` / `_runPhase` 里加分支解决的，绝不新增框架。**
> 这是本项目一贯做法（`boss.phases` 本身就是这么来的）。

### 3.1 【P0-A】回合触发 —— `trig` 支持 `{ turn: N }`

**动机**：做"第 N 回合必杀"，制造时限压力（主流做法：DPS check / enrage timer）。

**数据形态**
```js
phases: [
  { kind: 'burst', trig: { turn: 5 }, ... },      // 第 5 回合必放
  { kind: 'enrage', trig: .30, atk: .30 },        // 血量 30% 以下（旧形态照旧）
  { kind: 'enrage', trig: { turn: 8 }, atk: .50 } // 第 8 回合软狂暴
]
```

**实现**：`_genericPhases` 的判定行改成"血量 **或** 回合"：
```js
var hit = (ph.trig && ph.trig.turn != null)
  ? (this.round >= ph.trig.turn)
  : (boss.hp > 0 && boss.hp <= boss.maxhp * ph.trig);
```
`_phDone` 幂等机制原样复用 —— **零新状态**。

**验收**：`smoke` 加断言：构造 `trig:{turn:3}` 的桩 Boss，跑到第 3 回合必须触发、且只触发一次。

---

### 3.2 【P0-B】召唤物赋义 —— 让"多目标"变成机制

**动机**：现在召唤物是装饰。给三条语义，覆盖三种主流设计：

**数据形态**
```js
phases: [{
  kind: 'summon', trig: .60, n: 2,
  spec: {
    base: '杀手', name: '血影弟子',
    aura:    { kind: 'buff', atk: .10 },   // 活着 → Boss 攻击 +10%/只（不打越拖越难）
    onDeath: { kind: 'explode', mult: 1.2 },// 死时 → 对全体造成 1.2× 伤害（打掉有代价）
    // 或 onDeath: { kind: 'healBoss', pct: .08 }  // 死时 → Boss 回 8% 血（不能乱打）
  }
}]
```

**三种语义对应的玩法**

| `aura` / `onDeath` | 玩家学到的事 | 主流参照 |
|---|---|---|
| 无（现状） | "都是要打死的" | —— |
| `aura.buff` | **必须优先清**，否则 Boss 越来越强 | 魔兽"add must die" |
| `onDeath.explode` | **不能盲清**，要留群体减伤/错开时机 | 只狼"义手反向" |
| `onDeath.healBoss` | **打错就是帮 Boss 回血** → 逼玩家做目标优先级判断 | 暗黑"复仇词缀" |

**实现**：
- `aura`：在 `_tickTurnStart`（或现有回合开始处）遍历敌方单位，把 `aura.buff` 累加到 Boss 的 `_rage`（**复用现有狂暴乘区，不新增属性通道**）。
- `onDeath`：在 `_kill` / 伤害结算归零处，判断该单位是否带 `onDeath`，走对应分支（`explode` 复用 `_damage` 的全体路径；`healBoss` 复用 `_heal`）。
- 召唤物身上挂 `_aura` / `_onDeath` 字段，`makeSummon` 透传（与 `artKey`/`sprite` 同一套透传写法）。

**验收**：`smoke` 断言：带 `aura.buff` 的召唤物在场 3 回合后，Boss 攻击必须上升；召唤物死亡后必须回落。

---

### 3.3 【P1-A】破绽条 —— 给玩家一个"操作目标"

**动机**：现在玩家唯一的决策是"用哪招伤害最高"。破绽条引入**第二个轴**：用对属性打，能换来一个爆发窗口。

**数据形态**
```js
boss.break = { max: 100, gain: { elem: '雷', per: 25 }, down: 1 }
```
- 雷属性攻击每击 +25 破绽
- 满 100 → Boss 进入 `睡`（眩晕）1 回合（**复用现有状态，零新状态**）
- 破绽随时间自然衰减（每回合 -10），逼玩家**集中火力**

**UI**：血条正下方一条细条（复用 `G.UI.bar`），满时闪金。
**实现**：`_damage` 里判 `skill.elem === boss.break.gain.elem` 时累加；回合结束判满。

**为什么值得做**：这是**把灵根/功法的属性系统真正接进 Boss 战**的最短路径 —— 玩家第一次有理由"为了机制而不是为了数值"去配属性。

---

### 3.4 【P1-B】属性轮换 —— 逼玩家换招

**动机**：`boss.elem` 固定 → 配好克制就一劳永逸。

**数据形态**
```js
elem: ['金', '木', '水'],  elemCycle: 3   // 每 3 回合轮换；单字符串照旧兼容
```

**实现**：新增 `_unitElem(u)` 作为**唯一属性读取口**（现在代码里散读 `u.elem`），轮换时返回 `elem[(floor(round / cycle)) % len]`。
**兼容**：`typeof elem === 'string'` 时直接返回 —— **老 Boss 行为逐字不变**。

**UI**：Boss 名牌旁显示当前属性（已有属性色表 `G.Data.elem.color`）。

---

### 3.5 【P2-A】地格 —— 回合制的位置概念

**动机**：现在只有"前排/后排"，没有地形。

**设计**：战斗场地划 5×3 网格，格子可挂效果：

| 格效 | 效果 | 玩法 |
|---|---|---|
| `poison` 毒沼 | 站上去每回合掉血 | 逼玩家移动 |
| `leyline` 灵脉 | 站上去每回合回灵 | 抢位 |
| `fire` 火海 | 每回合掉血 + 火属性伤害 ×1.3 | 属性 + 位置耦合 |

**成本警告**：这是**唯一需要动战斗 UI 布局**的一项（要画格子 + 单位要有格位）。建议**留到 Boss 机制件跑通之后**再做，且先只做 1 个 Boss 试点。

---

### 3.6 【P2-B】阶段演出 —— 让玩家看见机制变化

**动机**：§1.2-④ —— 转阶段被漏看。

**设计**：转阶段时 0.4s 黑场 + Boss 台词 + 轻微镜头震动。
**实现**：`_runPhase` 开头插一个 `this._phaseFx = { t: 0.4, line: ph.line }`，`render` 里消费。
**零风险**：纯表现层，不动逻辑。`line` 字段可选，没写就不播。

## 4. 天道心魔对战（核心新设计）

### 4.1 硬约束：铁律不能破

`tiandao.js` 开头的铁律，**本文一切设计都必须在它之下**：

> **模型只产文本，不写存档、不算伤害、不发物品、不改天劫数值。**

这条不是保守，是**必要**：模型会幻觉、会超时、会被玩家改 prompt 套话。**一旦让模型碰数值，玩家就能靠改 prompt 秒杀 Boss。**

所以问题变成：**怎么在不碰数值的前提下，让天道真正"出手"？**

### 4.2 解法：意图枚举 + 本地映射

**模型输出的唯一合法结构**（在 `v2.7 §2.2` 的 JSON 契约上扩一个字段）：

```json
{
  "intent": "control",
  "predict": "封",
  "taunt": "汝之剑，吾已见之。"
}
```

| 字段 | 取值域 | 谁消费 |
|---|---|---|
| `intent` | **白名单 6 项**：`aggressive` / `defensive` / `control` / `burst` / `summon` / `heal` | 本地 → 出招倾向权重 |
| `predict` | **白名单**：`封`/`麻`/`毒`/`烧`/`睡`/`null` | 本地 → 低语预警文案 |
| `taunt` | **自由文本**（唯一不受限的字段） | 直接显示 |

**关键**：模型**不决定伤害、不决定数值、不决定技能本身**。它只从 Boss **已装配的技能池**里挑一个"倾向"：

```js
// 本地映射：intent → 选招权重（不是选招结果）
var INTENT_W = {
  aggressive: { atk: 1.4, heal: 0.6, shield: 0.6 },
  defensive:  { atk: 0.6, heal: 1.4, shield: 1.4 },
  control:    { status: 2.0, atk: 0.9 },     // 偏状态技
  burst:      { charge: 2.0, bigMult: 1.6 }, // 偏蓄力/大招
  summon:     { summon: 2.0, atk: 0.8 },
  heal:       { heal: 1.8, atk: 0.7 }
};
```

**收益**：
- 模型再离谱也**打不破平衡** —— 可选集是固定的，最坏情况是"这回合选了另一个合法技能"
- **离线也能跑** —— `intent` 由本地启发式给（见 §4.6）
- 模型的价值体现在**不可预测性**：同样的局面，人机会重复，天道会变

### 4.3 心魔三形态（纯本地可跑，LLM 只加风味）

> **设计原则**：心魔的**机制**必须 100% 本地实现。LLM 只负责"心魔说什么话"。
> 否则没配 API 的玩家会拿到一个残废玩法 —— 这在本项目是**不可接受的**。

#### M1 镜像心魔（Mirror）—— 打你自己
```js
boss.mirror = { pct: 1.10, skills: 'player' }
```
- 属性 = 主角快照 × 1.10
- **技能 = 主角已装配技能**（含冷却状态）
- **破法**：主角技能对自己**同属性抗性高** → 逼玩家换手段（道具 / 秘术 / 防御 / 破绽）
- **现有种子**：`DAO_TRIALS 执念化身` 已有 `snapshot: 1.10`，**只差"技能也复制"**这一步

#### M2 记忆心魔（Recall）—— 你杀过的东西回来了
```js
boss.recall = { source: 'kills', n: 2, aura: { kind: 'buff', atk: .08 } }
```
- 按**本世击杀记录**（`save.kills` 之类）召唤"记忆残影"
- 玩家看到自己杀过的物种回来 —— **叙事与机制同源**，这是"轮回"主题最直接的玩法化
- **破法**：清残影（否则叠加 `aura.buff`，见 §3.2）
- **依赖**：需要 `save` 里有本世击杀物种的累计表（**当前没有，需新增一个只增不减的计数表**）

#### M3 道心魔（Doctrine）—— 天道感最强
```js
boss.doctrine = { cycle: ['功法', '道具', '防御'], dur: 1 }
```
- 心魔**不主动攻击**，每回合**改写一条战斗规则**：禁用一类动作
- 玩家必须在"没被禁的动作"里找输出窗口
- **破法**：规划回合 —— 被禁功法这回合就吃药/防御，等下回合
- **这条最贴"天道以规则压人"的主题**：天道不跟你拼数值，它**改规则**

**三形态的递进关系**

| 形态 | 机制 | 玩家感受 |
|---|---|---|
| M1 镜像 | 复制你的**力量** | "我打不过我自己" |
| M2 记忆 | 复制你的**因果** | "我杀过的都回来了" |
| M3 道心魔 | 改写**规则** | "它根本不跟我打" |

> M1→M2→M3 = **力量 → 因果 → 规则**，三层递进，正好对应"逆命"的三重阻力。

### 4.4 注视值升级为「难度调节器」

**现状**：`save.watch` 只决定低语条数（`WATCH_ADD = { breakSmall:3, breakBig:15, boss:8, vessel:10, card:5 }`，每 30 注视解锁 1 条低语，上限 3）。

**升级**：注视值**同时**驱动心魔强度：

| 注视档 | 阈值 | 心魔形态 | 觉醒时机 |
|---|---|---|---|
| 无视 | < 30 | M1 镜像 | 血量 40% |
| 侧目 | 30–59 | M1 + M2 | 血量 50% |
| 注视 | 60–89 | M2 + M3 | 血量 60% |
| 天道临 | ≥ 90 | 全形态 + 属性加成 | 开场即觉醒 |

**这样"低语"和"战斗"就连起来了** —— 注视不再是装饰，是**难度的可见刻度**。

**关键：必须给高注视补偿**（否则玩家只会无脑压低注视）
- 高注视通关 → 额外仙晶（`xianli` 系数）+ 专属称号
- 即 **风险收益对等**：你可以低调苟活，也可以高调硬刚

**主题落地**：玩家第一次有了"**主动逆命**"的抓手 —— 少破境、少杀 Boss，天道就看不见你。**这就是"逆尘"这个书名第一次变成可操作的选择。**

### 4.5 低语 = 机制预警（把文本变成玩法）

**这是整个设计里最关键的一环。**

现状低语是**纯氛围**（"汝之剑，吾已见之"），玩家读完没有任何可行动的信息。

**改法**：低语携带 `predict` —— **预示 Boss 下一招的意图**。

| 低语（模型产） | `predict` | 玩家能做的 |
|---|---|---|
| "汝之剑，吾已见之。" | `封` | 下回合功法会被封 → 这回合先放掉大招 / 备好道具 |
| "血河将决，速避。" | `毒` | 下回合中毒 → 提前防御或治疗 |
| "汝之躯，不过皮囊。" | `烧` | 下回合燃烧（8% 当前血）→ 血量高时硬吃，低时必躲 |

**为什么这个设计成立**：
- **模型仍只产文本**（`taunt`），机制信息 `predict` 由**本地**给 —— 铁律不破
- **读文本有了玩法意义**：读得懂就能规避
- **读文本要花时间**，而战斗有 **30s 思考倒计时** —— 形成天然张力：**"听天道说话"和"想清楚出招"抢的是同一段时间**
- **离线玩家不吃亏**：`predict` 永远来自本地（Boss 下回合真要放什么，本地本来就知道），只是少了文学性

> 一句话总结：**天道说的每句话都是真话，但听懂要花代价。**

### 4.6 无 LLM 降级路径（必须有）

| 场景 | `intent` 来源 | `predict` 来源 | 玩家体验 |
|---|---|---|---|
| `mode: 'remote'` 且模型正常 | 模型 | **本地** | 完整 |
| `mode: 'remote'` 但超时/报错 | 本地启发式 | **本地** | 几乎无差别（少点文采） |
| `mode: 'off'` | 本地启发式 | **本地** | 完整机制，无低语文本 |

**本地启发式**（`intent` 的兜底）：
```js
// 极简规则，够用即可 —— 目的是"有变化"，不是"最优解"
if (boss.hp < .3 && cdReady('大招')) return 'burst';
if (boss.hp < .5 && !summoned)         return 'summon';
if (playerHp < .3)                     return 'aggressive';
return ['aggressive','control','defensive'][round % 3];
```

> **降级路径不是"备胎"，是主路径。** 设计时以"没有模型"为前提，模型是加分项 —— 这样才不会被 API 可用性绑架。

## 6. 验收清单（机制设计自检）

**每个 Boss 上线前对照 §2 六问**，并额外确认：

- [ ] 玩家能用**一句话**说出这个 Boss 的打法区别（说不出 → 纯数值，退回重做）
- [ ] 破法**在玩家的常规 build 里可达**（不能要求玩家专门配一个平时没用的属性）
- [ ] 机制**有预警**，且预警信息**不依赖模型**（离线玩家也能看到）
- [ ] 机制**不破坏铁律**：没有任何一条让模型影响数值
- [ ] 存在**降级路径**：没配 API、模型超时，机制仍完整
- [ ] 打不过时有**出路**（逃 / 降难度 / 换 build）

## 8. 一句话总结

> **Q2（Boss 没层次）先于 Q1（天道没出手）解决。**
> 机制件补到"每个 Boss 教一件事"之后，天道才有东西可操控 ——
> 而它操控的方式**不是给 Boss 加数值，是给 Boss 换意图**：
> **模型产文本 → 本地映射意图 → 意图只影响"从固定池里挑哪个" → 平衡不可能被打穿。**
> 低语第一次承载机制预警，**"听天道说话"与"想清楚出招"抢同一段 30 秒** ——
> 而注视值从装饰变成刻度，**"低调苟活"第一次成为玩家主动的、有代价的选择**。
> 这就是《逆尘》的主题在玩法层的落地。
