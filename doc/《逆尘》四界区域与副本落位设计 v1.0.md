# 1. 一句话结构与关键数字

> **一世之内可连续飞升**：入世时天道抽定**起始界**，把 5 个副本入口随机撒进该界区域、顺序随机；
> 清掉第 5 个副本即**该界通关**，**普通难度即可飞升**上一界；已通关的界转为「下界」，可自由回访（只刷资源与副本）。
> **地狱难度是可选挑战**，通关给称号 + 跨世永久全属性 +10% + 一枚**道之钥匙碎片**；三枚碎片齐才开道界。

| 项 | 值 |
|---|---|
| 界数 | **4**：凡、灵、仙 + 隐藏道界 |
| 区域总数 | **28** = 凡 **9** + 灵 **5** + 仙 **9** + 道 **5** |
| 一世可通界数 | **≤ 3**（凡 → 灵 → 仙）；飞升不强制、**普通难度通关即可** |
| 起始主界 | **1**（天道抽定，未通关界优先；锚世固定凡界）；飞升后主界随之上移 |
| 每界副本 | **5**（2 大 3 小、第 5 必大，顺序随机；见副本 v3.2 §6.1） |
| 入口落位 | 从**当前界**的区域内**无放回抽 5 个**作为入口所在区域 |
| 建筑 | **全部可进**，内部由**程序化模板**生成（9 类模板） |
| 区域尺寸 | 室外 36×24 ~ 50×40；室内 24×17 ~ 30×17（沿用 16px 格） |
| **地狱难度** | 每界独立设定；通关给**称号 + 跨世永久全属性 +10% + 道之钥匙碎片 ×1** |
| **道界开启** | **集齐三界地狱碎片**（取代副本 v3.2 §3.3 的"地狱通关仙界掉整把钥匙"） |

# 2. 核心循环（v1.1 修订）

## 2.1 一世之内的推进

| 阶段 | 规则 |
|---|---|
| 锚世（第 1 世） | 固定**凡界**，固定教学（青溪镇 → 翠微山 → 赤牙洞狼王），不走随机池 |
| 浮世（第 2 世起） | 入世时天道抽定**本世起始主界**，并把 5 个副本入口撒进该界的区域 |
| 界内推进 | 5 个副本按**槽位顺序**解锁（槽位决定 Boss gl，副本 v3.2 §6.2）；清掉第 5 个 = **该界通关** |
| 飞升 | **不强制**；飞升台自选时机飞升上一界。**普通难度通关即可，不需要地狱** |
| 一世多界 | **一世之内可以连续飞升**（凡 → 灵 → 仙），理论上能一世打通三界 |
| 战死 | 仙力结算 → 轮回 → 重抽起始主界与入口落位 |

> ⚠️ **v1.1 修订**：v1.0 写的"一世一主界"（每世只能推进一个界）**作废**。
> 现行口径：**主界 = 当前正在推进的界**，随飞升上移；已通关的界转为「下界」，可回访。
> 这与副本 v3.2 §2.2「顺序解锁 + 飞升不强制」一致。

## 2.2 起始主界抽取

```
已解锁界 = 凡 ∪ {灵 若 凡已通关} ∪ {仙 若 灵已通关} ∪ {道 若 三碎片齐}
本世起始主界 = 已解锁界中，以「未通关的界优先」抽 1 个
```

- **未通关的界优先**：保证主线能推进（不会反复回到已通关的凡界刷）。
- 若所有已解锁界都已通关，则随机回访其中一界（“长草世”，收益走重复刷取表）。
- 起始主界写 `save.mainWorld`；**飞升后 `save.mainWorld` 随之上移**（主界 = 当前界）。

## 2.3 下界回访

| 界 | 区域可进 | 副本入口 | 主线推进 |
|---|---|---|---|
| **当前界** | ✅ 全部 | ✅ 5 个（天道落位） | ✅ |
| **已通关下界** | ✅ 全部（回访） | ✅ **仅已通关的副本**（可重复刷取） | ❌ |
| **未解锁上界** | ❌ | ❌ | ❌ |

- 回访通道：每个界的**首区**（凡 F1 青溪镇 / 灵 L1 雷泽荒原 / 仙 X1 南天门 / 道 D1 道则回廊）设一座**界门**，
  解锁后即可往返。
- 回访下界的收益按**该界的资源口径**（副本 v3.2 §9），不做跨界汇率折让。
- 回访下界**不刷新**当前界的副本槽位进度，两者进度各自独立记录。

## 2.4 野外遇怪刷等级（v1.1 明确）

- 区域地图的**非安全区**走暗雷（12%/步、进图前 3 步保护），遭遇给**灵气（等级经验）与灵石**。
- 刷等级是**正当路线**：灵气攒够即可尝试破境（破境仍需破境丹 + 天劫，见破境 v2.6），
  所以「刷野怪 → 攒灵气 → 破境 → 打通副本」本身就是主循环之一。
- 遭遇怪等级按**区域 gl 分段**（本稿 §3 每区的 `zones`），越靠后的区域怪越强、收益越高。
- 刷取受**寿元（每 10 场 +1 岁）+ 战死风险**约束（副本 v3.2 §8.2），不做体力系统。

## 2.5 地狱难度：称号 / 永久加成 / 道之钥匙碎片（v1.1 新增，取代副本 v3.2 §3.3）

三档难度**每个界独立设定**（新游戏选定默认档，之后可为每个界单独调档）：

| 难度 | 通关该界第 5 副本的产出 |
|---|---|
| 普通 / 困难 | 解锁上一界；**不**给碎片、**不**给称号 |
| **地狱** | 以上全部 **+ 该界专属称号 + 永久全属性 +10% + 该界的「道之钥匙碎片」×1** |

| 界 | 称号 | 永久加成生效时机 | 碎片 |
|---|---|---|---|
| 凡界 | 破狱·凡尘 | 飞升**灵界**之后 | 道之钥匙碎片·凡 |
| 灵界 | 破狱·灵渊 | 飞升**仙界**之后 | 道之钥匙碎片·灵 |
| 仙界 | 破狱·仙穹 | **道界开启**之后 | 道之钥匙碎片·仙 |

- **永久**指**跨世保留**（写 `meta`，不随轮回清空）；加成为**全属性 +10%**（攻/防/血/速同乘）。
- 三枚碎片齐 → `meta.progress.daoKey = true` → **道界开启**
  （取代旧规则"地狱难度通关仙界掉整把钥匙"，副本 v3.2 §3.3 相应作废）。
- 地狱难度本身是**可选挑战**：普通难度通关即可飞升，地狱只为称号 / 加成 / 碎片。
- 难度可**回刷**：已通关的界可用更高难度重打第 5 副本补拿称号与碎片（`meta` 去重，只发一次）。
- 地狱难度仍沿用副本 v3.2 §3.2 的倍率（Boss HP ×1.8 / ATK ×1.55、资源 ×0.6、**Boss CD −1**）。

# 4. 区域规格

## 4.1 区域字段（`data/regions.js` 的紧凑规格）

```js
{ id:'fan5', n:'黑风岭', world:'fan', theme:'匪寨山地',
  map:'gen',              // 'gen' = 生成器产出；给了具体 map id 则复用现有手写地图
  w:42, h:30, ground:'grass',
  buildings:[ {k:'gate', n:'寨门楼', w:5, h:3}, {k:'tower', n:'哨塔', w:2, h:3},
              {k:'hall', n:'聚义厅', w:6, h:4}, {k:'house', n:'匪舍', w:4, h:3, n2:3} ],
  exits:[ {to:'fan1', side:'south', label:'青溪镇'}, {to:'fan6', side:'east', label:'幽篁谷'} ],
  zones:[ {id:'front', y0:20, y1:29, enc:{min:3,max:6}, sp:{'赤炎狼':60,'青纹蛇':40}, pair:20},
          {id:'back',  y0:0,  y1:19, enc:{min:6,max:10}, sp:{'树精':50,'赤炎狼':50}, pair:30} ],
  npcKinds:['villager','keeper'],
  gate:false }            // true = 本区有界门（各界的首区）
```

## 4.2 生成规则（`core/regiongen.js`）

由规格**确定性生成**（种子 = `worldSeed + ':' + regionId`），保证同一世重进区域布局不变：

1. **边界围合**：室外用 `tree`/`rock`/`wallrock`（按 `ground`），**跳过出口格**（否则门被堵死）。
2. **主干道**：按 `exits` 的方位生成一条贯通路径（改 `ground` 为 `path`），保证**任意两出口互通**。
3. **建筑落位**：沿主干道两侧依次摆 `buildings`，**整块 solid**；同名带 `n2` 的按数量复制。
   每栋建筑的**门交互点登记在正下方一格**（沿用 mapgen 的既有约定）。
4. **围栏/散景**：避开 `occupied` 与 `path`，与建筑保持 1 格间距。
5. **遭遇分区**：`zones` 按 `y` 划分，权重与编队沿用副本 v3.2 §5.3 的换皮表。
6. **副本落位点**：主界被抽中的区域，在**远离出口的空地**放一个 `special` 交互点（`kind:'entrance'`）。

## 4.3 硬约束（会被 `smoke.js` 卡）

- 每个 `exits[].to` 必须是合法区域 id，且**出口格不被 solid 堵死**。
- 建筑整块 solid；每栋建筑**必须有门交互点**且**从出生点 BFS 可达**。
- 区域 `spawn` 必须在可行走格上。
- 若 `gate:true`，界门交互点必须存在且可达。

## 5.2 生成与接线

- **室内 map id**：`int.<regionId>.<buildingId>`（如 `int.fan5.b3`），**按需生成、确定性可复现**。
- **进门**：在区域内踩到/面向建筑门格 → `_transition({to:'int.<regionId>.<buildingId>', spawn:室内出生点})`。
- **出门**：室内 `exits` 单条，`to` 回 `regionId`，`spawn` 为建筑门格**正下方一格**（避免出门卡在 solid 里）。
- **模板换皮**：同一模板按**区域主题**换调色板与家具配色（如 `hall` 在 `ling3 血煞总坛` 走血色调、在 `fan5 黑风岭` 走木色调），
  保证“同一模板不同观感”。
- **NPC 命名**：室内 NPC 由区域主题 + 建筑类型生成（如 `落霞镇·铁匠`），只有闲聊，不做任务（避免与剧情冲突）。
- **确定性**：种子 = `worldSeed + ':' + interiorId`，同世重进同一栋建筑布局一致。

## 5.3 不做

- 不做多层建筑（塔/阁只有一层，用“楼梯口描述”文字带过）。
- 不做建筑内部的战斗与宝箱（资源只放在区域地图上，避免“进屋必打架”）。
- 不做可破坏家具。

# 6. 副本入口天道随机落位（本稿新增，取代“菜单式秘境枢纽”）

## 6.1 落位算法

```js
function rollWorldEntrances(rng, worldId, meta, save) {
  var regions = regionsOf(worldId);                 // 凡9 / 灵5 / 仙9
  var picked  = sample(rng, regions, 5);            // 无放回抽 5 个区域
  var set     = rollDungeonSet(rng);                // 副本 v3.2 §6.1：2 大 3 小、第 5 必大、前 4 洗牌
  var out = [];
  for (var i = 0; i < 5; i++) {
    out.push({ slot: i, arch: set[i].id, region: picked[i].id, stage: 0 });
  }
  return out;                                        // 槽位 i ↔ 区域 picked[i] ↔ 原型 set[i]
}
```

- **槽位决定 Boss gl**（副本 v3.2 §6.2），原型只决定机制/名号 —— 随机顺序不崩坏数值。
- 落位结果写 `save.entrances[<界>]`（**按界分桶**，回访下界时原落位仍在）。
- **候选区收紧（v1.1）**：只从**生成型、非安全区**里抽 ——
  ① 安全区（市镇 / 天宫门阙 / 首区）是休整交易的地方，不该冒裂隙；
  ② 凡界 F1–F3 是教学锚定区（复用现有手写地图），没有裂隙位。
  收紧后候选数：**凡界 5 / 灵界 5 / 仙界 7**，都够抽 5 个。
  > 为此把仙界的**兜率天宫 / 蟠桃园 / 天枢阁**由安全区改为非安全区（并补 `zones`）——
  > 天宫重地本就该有守卫傀儡，改动与主题一致。
- 灵界只有 5 个候选 → 恰好每区一个入口；凡界 5 / 仙界 7 → 抽 5 个，其余为纯探索区。

## 6.2 入口交互

| 项 | 规则 |
|---|---|
| 地图表现 | 区域内的 `special` 点（`kind:'entrance'`），绘制为「秘境裂隙」；未解锁槽位显示为**黯淡裂隙** |
| 交互 | 面向/踩到 → 弹「副本入口面板」：副本名、推荐境界（槽位 gl）、Boss 名号、秘术已得/尚缺、进入 |
| 解锁 | 仅当前槽位开启（`save.dungeonSlot`）；已通关入口永久保留、可重复刷取 |
| 保留 | 保留现有 `dungeon` 场景作为**面板实现**，入口由「菜单进入」改为「区域点位触发」 |

## 6.3 下界回访的入口

- 已通关下界的入口**全部解锁**（用于刷取），但**不刷新主界槽位**。
- 回访界只保留该界**已通关**的副本入口，未通关的槽位在回访界不出现。

## 11.2 实现备注（与原稿的差异 / 踩坑）

1. **`mapgen` 修掉一处既有隐患**：登记门交互点后**没有把门格标成"已占用"**，
   于是随机散布的树/石可以正好落在门格上把门堵死 —— 区域图上表现为"那栋建筑永远进不去"，
   而且**不报任何错**。现已补 `mark(doorX, doorY)`，并由 `regions.contract` 做反例验证
   （撤掉这一行立刻报 2 处）。
   ⚠️ 这条对**既有地图同样生效**（镇上民居门也可能被树堵）；修复后 town/field 的散布布局会有微调。
2. **建筑门可达性在放置时验证**：从门格沿非建筑格 BFS 到最近道路，通就落位、不通就**整栋回滚重摆**。
   比"只允许贴着路放建筑"宽松得多，荒野区域也能有自然的散落布局。
3. **`dungeons.rollSet()` 用的是 `Math.random`**（既有实现），所以**入口落位的原型顺序不完全可复现**；
   区域抽取走 `G.rng`（种子化）可复现。若要全程可复现，需把 `rollSet` 改成接受 RNG 参数。
4. **道界的 5 个入口是固定试炼**（`arch=null, fixed=true`），不参与随机池 —— 与副本 v3.2 §6.3 一致。
5. **凡界 F1–F3 复用现有手写地图**（`town`/`field`/`cave`），区域 id 与场景 id 不一致，
   靠 `regions.mapIdOf()` / `regionIdOf()` 双向映射；这样 M0 教学链与既有测试契约零改动。
